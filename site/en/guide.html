Guide

Every feature, in the order you meet it on screen. If you are new, the 101 walks you through the whole process first.

Tab 1 Familiarise & Code

Documents and participants

  • Default participant: who untagged text in a document belongs to. For a one-to-one interview, this is all you need.
  • Detect speakers: tags lines that start with “Name:” (or “Name：”, also inside brackets) as that speaker. I, Q, Interviewer, Moderator, Facilitator, Researcher and their Japanese equivalents become interviewers automatically and are not counted as participants.
  • Tag by hand: select text and click Tag in the participant list, or drag a participant onto a line. Each character has exactly one speaker.
  • Edit a participant: hover and click the pencil to change the label, mark them as interviewer, and add attributes (one key: value per line). Attributes feed Table 1 and the extract filter.
  • Notes: familiarisation notes for each document.

Full-text search

The search box at the top left (Ctrl+F) searches the text of every document. Upper and lower case (and full- and half-width characters) match each other. Matches are listed by document with their context; click one to jump to it. Enter goes to the next match, Shift+Enter to the previous one, Esc clears the search. While the extract filter (below) is on, only that group's text is searched.

Edit, merge, split or delete a code

Open the editor with ⋮ next to the code.

  • Change the name, description and colour.
  • Merge: choose a target and save. Every extract moves to the target and this code disappears.
  • Split…: tick extracts and name the code they should carry (new or existing). Options: Put the code in the same theme(s) and Also keep the original code on the ticked extracts.
  • Delete: extracts with no other code are removed too.
  • Why? (optional): kept in the audit trail as the reason for a rename, merge, split or delete.

Counts

The number of extracts and participants per code is hidden by default. Show counts toggles it (shared by tabs 1 and 2).

Tab 2 Themes

Board

  • Create a theme: type in New candidate theme… and click Theme. Subthemes: + Subtheme on a card (one level).
  • Add codes: drag from the code pool onto a card, or pick one from + Add a code… on the card (works with a keyboard or touch). Drag between cards to move; click × or drop it back on the pool to remove. A code can sit in several themes.
  • A theme is not a box of codes: themes are built by reading and interpreting extracts, and codes are a tool for that. Re-read the extracts once codes are in a theme; if only some of a code's extracts belong to another theme, split the code.
  • Status: Candidate, Reviewed, Defined, Set aside. Not a sequence of steps: a status moves back as well as forward. Changing the status offers a small, optional box to say why. A theme marked defined without a definition gets a gentle hint on its card.
  • Phase 4 · Review against the data: questions at two levels (do the coded extracts cohere / does the theme capture something meaningful in the whole dataset) and review notes. There are no checkboxes; writing a review note puts a ✓ on the heading.
  • Phase 5 · Define & name: the central organising concept, scope and boundaries, and relation to other themes.
  • Show extracts: every extract of the theme and its subthemes, key extracts first. Click one to go back to the text.
  • Filter by status, and reorder themes with ↑ ↓.

Extract filter

Extracts from everyone, above the code list in tab 1 and the code pool in tab 2, narrows extracts to one attribute value (e.g. Role: Care worker) or one participant, in the code list, theme cards and full-text search. It is for reading across groups: counts, the theme structure and exports are not affected.

Gentle hints

Theme names (in the phase 5 section), subthemes (when a theme has them) and the number of themes (above the board, once reviewing has begun) come with questions rather than numerical rules of thumb. A theme marked defined without a definition gets a small hint on its card. Hints never block anything.

Map

  • Drag themes to arrange them (subthemes follow). Reset layout returns to the automatic layout.
  • Click Link themes, then two themes in turn, to join them. Click a line to name the relationship or remove it.
  • Map (.svg) saves the map; the Word write-up includes it as Figure 1. Themes set aside are not shown.

Tab 3 Audit & Journal

Audit trail (automatic)

Imports; codes created, renamed, merged, split and deleted; themes created and changed, with their status; review notes and definitions; speaker tags; project setup changes; and single coding actions — each with a time stamp and the researcher's name. By default the list shows interpretive decisions only, without single coding actions. Add a note attaches a later note to any entry.

Reflexive journal

  • Open it from any tab with Ctrl+J (⌘+J). On wide screens it sits beside your work; on narrow screens it overlays it. In tab 1, when the screen is not wide enough, it covers the codes column on the right so the text does not get squeezed. Closing it never loses a draft.
  • Types: reflexive memo, familiarisation note, analytic decision, session note, supervisor / team meeting, positionality. A meeting entry starts with an outline.
  • The open document, extract or theme is attached automatically (click × to detach).
  • Each entry saves the theme structure at that moment. Structure then shows it, together with what has changed since.

Tab 4 Writing up

Analytic narrative (phase 6)

The tab opens on writing, not on tables: Overview of the analysis, a narrative for each theme and subtheme, and General discussion: conclusions across themes. Under each theme, Extracts to draw on → Insert puts an extract at the cursor.

Storage and backups

  • Your data is stored only in the browser you are using (IndexedDB). Nothing is sent to a server. Changes are saved as you go (Saved at the top).
  • One project per browser. To switch, back up, use New / Reset, and later Restore backup.
  • Work in one tab at a time. If the same project is also open in another tab or window, a yellow bar at the top of both says so: each tab keeps its own copy and does not see the other's changes, so they can overwrite each other. Close one of them.
  • Each place you open the app from has its own storage. The online version (this site), the offline version (a file you double-click), different browsers and private windows all keep separate data. With the offline version, some browsers no longer find earlier data once the folder holding ta_canvas.html is moved: back up before moving it.
  • Clearing the browser's site data (cookies and site data) deletes the project. Back up regularly. The top bar quietly shows how long ago you last did (in amber once there is data and no backup from the last week).
  • A backup (.json) contains the full text of your documents. Store it as carefully as your raw data.

Working with others

In reflexive TA, a second analyst is there to enrich the interpretation, not to check it. The app therefore has no agreement statistics and no merging of two projects.

  • Supervisor or co-author as critical friend: the main analyst codes and develops themes, and shares the write-up (.docx) or the backup (.json) before a meeting.
  • Analysing in parallel: each analyst works in their own project. Compare interpretations — themes, definitions, the map, the narrative — rather than code-by-code matches.
  • Analysing in turn: hand the project over with Backup and Restore. With a name in Researcher, every action records who made it.

After a discussion, write a journal entry of the type Supervisor / team meeting. It starts with an outline: who took part, where your readings differed, what each rested on, how you handled it and what changed.

Other QDA software (REFI-QDA)

The app reads and writes REFI-QDA projects (.qdpx), the exchange format shared by QDA programs.

  • Export (tab 4): documents, codes, coded extracts and memos, participants and attributes, themes and subthemes (as sets of codes, with definition and narrative), familiarisation notes, and journal entries.
  • Import (Import): everything is added to the current project. Codes and participants with the same name are joined; code folders and sets of codes from other software become candidate themes. Non-text sources (PDF, audio, images) are skipped. One Undo removes the whole import.
  • The audit trail, theme status and review notes, and the map have no place in the standard and are not exported. Use Backup for a complete copy.
⚠️ Not yet tested with other programs

Exported files validate against the official REFI-QDA schema, but round trips with ATLAS.ti, MAXQDA, NVivo and others have not been tested yet, and each program interprets the standard a little differently. Check the result after moving a project and keep a backup. Reports of what works and what does not, with the program and version, are very welcome in Issues.

Reporting (RTARG)

The RTARG mapping goes through each item of the Reflexive Thematic Analysis Reporting Guidelines (Braun & Clarke, 2024): what the app supports, what remains the researcher's writing, and what still needs work. Use it as a check when you write up.

FAQ

Is my data sent anywhere?

No. Even the online version only loads the app; your data is never sent. It is stored only in your browser.

Can it calculate inter-coder agreement (e.g. kappa)?

No. In reflexive TA coding is interpretive, and agreement is not a marker of quality (Braun & Clarke, 2019, 2022). If you need agreement for a codebook approach, use other software.

Can AI code or summarise my data?

No, by design. Reading and interpreting the data is the researcher's work.

I need prevalence in my paper. Can I get it?

Tick Include prevalence in the Writing up tab to export participants per theme and the theme × participant table (the numbers of extracts and codes in the summary, and the counts in the participant table and code list, appear only then too). Reflexive TA does not justify themes by frequency, so consider whether it serves your argument first.

Does it work on a tablet or phone?

It will display. Codes can be added to themes without dragging, but coding relies on selecting text, so a desktop browser is recommended.

Can I work on several projects?

One browser holds one project. Switch with Backup and Restore, or use a different browser for each project.

The highlights on coded text are too bright.

Under the gear menu, set Coding highlights to Soft (easier on the eyes) or Underline only. It changes only how highlights look, not your data or the colours of your codes.

My text shows garbled characters.

.txt and .csv files are detected as UTF-8, UTF-16 or Shift_JIS. If text is still garbled, re-save the file as UTF-8 and import it again.

How do I correct an imported text?

Imported text is fixed. Remove the document and import the corrected file (you will need to code that document again). It is best to check transcripts before importing.

Where do I report a bug or suggest a feature?

In GitHub Issues. Feedback from qualitative researchers is especially welcome.
